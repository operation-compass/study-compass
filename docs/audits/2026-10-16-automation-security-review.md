現時点で**本番自動マージとGAS定期トリガーは開始しない**。GitHubで既存READYの差分ゼロ判定、検証用の新規設問追加、GASのGitHub同期とPR提案ジョブの起動は確認したが、監査の独立性・公開時の改ざん防止・本番の問題単位検証は未完成。

## 重大指摘

1. **真正性の保証不足**：`scripts/select-ready-candidates.cjs` は台帳のPASS×3、日時、LOW、SHA一致とHTTPS形式のURLを検査する。一方、3つの監査を実際に独立実施した本人・権限・個別の根拠内容を検証していない。ステージングJSONの `approval.export_source` は文字列で、署名やGitHub保護環境による独立認証ではない。**監査条件を満たしているという記録は、監査が実施された事実の暗号学的な証拠ではない**。
2. **SHAの対象漏れ**：`STUDY_FIELDS` と `select-ready-candidates.cjs` のfieldsは `grade`,`unit_major`,`unit_minor` を含まないが、新規問題の本番Web生成には使う。分類変更だけではSHAが変わらない。既存データのSHA互換性を壊さないよう、**V2ハッシュ仕様・データ移行・回帰テストを別実装**する。現行V1で新規問題を無条件自動公開しない。
3. **実際のPR作成権限未検証**：最新のGitHub Actions成功ログは `No Web delta. No PR.`。差分ありの `git push` と `gh pr create` は一度も実行されていない。権限・リポジトリ設定が未確認。現在のPR #12も未マージ。
4. **公開処理未完了**：`propose-ready-release.yml` はdraft PRを作るが、既存のCloudflareデプロイは`main`へのpushのみで動く。自動マージ、信頼境界、ロールバックと変更後の問題ID/正答/解説検証は未実装。本番への自動マージはまだ導入しない。
5. **継続バッチの枯渇**：GASは候補を列挙するが、Web準備ではREADYが5件超なら例外。全5,208問を安全に5件ずつ継続処理する進捗カーソル／未公開差分からの選定／重複防止が未設計。
6. **監査日付の部分検証**：最新選別コードは未来日を拒否するが、日付の存在と書式のチェックだけでは日単位の実監査や監査順序を証明できない。GAS側のCHECK抽出条件と公開側のREADY最終条件にも差がある。

## 安全に進める順番

- A: 公開データのすべての意味的フィールドを対象とするハッシュV2を定義し、既存SHAと互換性を保った移行計画を作る。
- B: 正確性・品質・技術を独立した主体と根拠に結びつけ、証拠不十分ならHOLD。
- C: 合成READY差分を使って隔離ブランチで実PR作成権限を検証。偽問題は絶対にmainへマージしない。
- D: 実READY差分の検証環境・本番反映・設問単位のWebテスト・失敗時復旧を接続。
- E: 差分優先・最大5問・再開可能なバッチ同期を実装し、最後に2時間トリガーを設定。

**今回の再監査では、Google Sheets・稼働GAS・本番HTML・Cloudflareの更新を行わない。**

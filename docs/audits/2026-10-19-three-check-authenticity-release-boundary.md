# 新3チェックの真正性・公開接続に関する未解決の安全要件（2026-10-19）

## 実コードから確定したこと
- `main/data/publishing/auto-publication.json` は `enabled: true`。既存の旧READY経路は自動マージとCloudflareデプロイを実行し得る。
- `main/scripts/verify-auto-publication.cjs` の `verifyEvidence` は証拠MarkdownのSHA256と、JSONファイル内の対応する監査レコードを照合する。**JSON内の一致は監査者本人・署名の真正性を保証しない**。コード上、暗号署名検証や独立した監査者レジストリの認証は見当たらない。
- `scripts/simple-three-check-gas-adapter.cjs` は承認元が未接続のため `release_authorized:false` / `HOLD` を強制する。合成PASSでも解除しないテストがある。
- 正本の `Web自動公開｜新3チェック記録` は既存タブ（172タブ中）であり、A1:D1000の確認ではヘッダーのみ、実監査0件。新タブを重複作成しない。
- 現行GASの旧READY候補0件の早期returnと差分比較は、新監査レコードのみのステージング更新を通さない。既存の送信先ブランチは自動公開経路につながる。

## リリース前の受入条件（すべて必須）
1. **監査主体**: accuracy / quality / technicalの責任者・権限・監査対象の分離を、候補JSONから独立した信頼済みレジストリで照合する。同一主体による別名義や自己申告は不可。
2. **真正な証拠**: 問題ID・版・SHA・審査役割・審査者・審査日時・証拠ファイル実バイトのSHAを結び付ける。承認者の署名または同等の認証済み承認イベントを検証する。JSON内に「署名済み」と書くだけでは不可。
3. **信頼境界**: 監査記録、承認レジストリ、候補データを同一の未信頼ステージングコミットから取得しない。GitHubのコミット作者名やファイル一致だけで人間の独立承認を認定しない。
4. **隔離テスト**: 未署名、失効、別問題、別版、別SHA、同一監査者、証拠改ざん、重複パス、古い承認、0件の各ケースでHOLD。既存本番の `enabled` とトリガーは変更しない。
5. **接続テスト**: GASの旧READY候補0件でも、新方式のshadow候補を読み取り専用で確認できる。新監査だけの差分を検出し、公開ワークフローを誤起動しない。
6. **本番移行条件**: 隔離環境で1問の真正な監査→認証済み承認→ステージング→PR検証→公開物2ファイル一致→Cloudflare配信一致までの記録を残す。ロールバック失敗時の手順も検証する。条件を満たすまで新方式公開0件、PRはdraft。

## 禁止事項
- 旧監査PASSを新方式のPASSに変換しない。
- `HOLD` や `release_authorized:false` を外して通さない。
- 稼働中GAS、本番main、ステージング送信ブランチ、既存スケジュールをこの検討だけで変更しない。
- Codexスケジュールを新設・再開しない。

この文書は安全要件の記録であり、監査・承認の認証が完成したという主張ではない。
